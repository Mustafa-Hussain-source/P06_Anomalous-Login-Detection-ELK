In this sprint, we built an end-to-end adaptive login defense and security monitoring platform that combines a FastAPI backend, a simulation-driven threat model, and a full ELK plus Wazuh observability stack into one practical, demo-ready system. At the application layer, the backend implements security use cases such as brute-force detection and account lock (UC-012), geofence-based access blocking and blacklist enforcement (UC-013), session hijack detection with forced session invalidation (UC-014), and impossible-travel detection with MFA step-up mitigation (UC-015). Every login attempt is normalized, risk-scored, and persisted with contextual signals like IP, country, device fingerprint, latitude/longitude, suspicious flags, and mitigation metadata, allowing us to prove that prevention decisions are explainable and auditable. We also added deterministic simulators that trigger each use case reliably, making it easy to reproduce attacks and validate controls under repeatable conditions. On the telemetry side, we wired Logstash, Filebeat, and Elasticsearch so both application events and Wazuh-originated logs are ingested into searchable indices, while Kibana provides immediate analytical visibility for troubleshooting and evidence collection. In parallel, we integrated Wazuh manager, Wazuh indexer, and Wazuh dashboard so security events can be monitored in a SOC-style interface, with custom active-response scripts available for automated actions such as account lock, IP block, session kill, and MFA escalation. Because our architecture uses both Elasticsearch and Wazuh indexer, we built synchronization automation that mirrors selected indices continuously, ensuring data parity for dashboards and reducing manual operational overhead. To make operations simple for demos and testing, we scripted the full workflow: launching the API, bringing up containers, opening the local HTML dashboard, running backend verification checks, and starting continuous synchronization. We also added verification scripts that confirm API reachability, core mitigation behavior, event and mitigation log population, and end-to-end readiness, so failures are detected early and reported with clear pass/fail output. Finally, we documented command-first execution through a compact command guide and a one-command orchestrator, turning a multi-service security platform into a repeatable, low-friction startup experience suitable for grading, stakeholder demonstrations, and future extension into production-grade controls.
